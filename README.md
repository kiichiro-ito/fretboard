# Fretboard Trainer

指板上の**空間パターン認識を高速化**するための練習ツール。

「音名 → 度数計算 → スケール名 → 運指」という変換経路を経由させず、
**キー/コード提示 → 運指パターン**を直結させることを狙っている。

## 起動

```bash
npm install
npm run dev
```

本番ビルド:

```bash
npm run build
npm run preview
```

`dist/` は相対パス (`base: './'`) でビルドされるので、静的ホスティングでもサブディレクトリでも動く。
Service Worker + manifest を同梱しているので、一度開けばオフラインで練習できる
(スマホではホーム画面に追加するとスタンドアロン起動になる)。

スマホの実機で使うときは、PC とスマホを同じ LAN に置いて:

```bash
npm run dev -- --host
```

表示された `http://<PCのIP>:5173` をスマホで開く。

## モード

| モード | 内容 |
|---|---|
| スケール・リファレンス | 指定キー/スケールを指板に表示する辞書。度数/音名/非表示のラベル切替、ボックス(ポジション)表示、親キー・特性音の表示。12F / 15F / 24F 切替 |
| ポジション・フィル ★ | 「キー Bm / F#m / ガイドトーン」のように、コードとお題を見て指板の枠内をタップする。本ツールの核心 |
| 音名当て | 指板上の1点の音名を12択で答える。制限時間つき。出題範囲は 24F まで |
| キー×度数 | 「Bm の V はどのコード?」「Bm の F#m は何度?」の双方向 |
| ダイアトニック暗記 | 逆引き (コード → それを含むキー) / 一覧を埋める / 構成音 の3形式 |
| キー当て | コード進行を見てキーを答える。答え合わせで各コードの度数が出る |

### キー当ての「正解が一意に決まる」保証

平行調 (C と Am) は構成音が同じなので、進行によってはキーが決まらない。
`Dm - G - C` は C にも Am にも取れるし、`C - G` に至っては情報が足りない。

そこで出題を作るたびに [analysis.ts](src/music/analysis.ts) の判定器に通し、
通らなかった出題は捨てている。判定器は24キーすべてを採点し、

- 説明できないコードがあるキーは失格
- トニックで終わる / 始まる、V7 → I の終止、マイナーキーの V7 に加点
- 2位との差が 3 点未満なら不合格 (平行調と差がつかない)
- トニックが一度も現れない進行は不合格
- コードが3個未満は不合格 (情報量が足りない)

という条件を課す。実際この判定器は、最初に用意したテンプレートのうち
`VI - IV - I - V` と `Im - Vm - ♭VI - ♭VII` の2つを「平行調と差がつかない」として弾いた
(どちらも終止が平行調側に流れる進行だったので、終止を直した)。

進行は**キー + 度数**で持っているので ([progressions.ts](src/music/progressions.ts))、
全キーに移調して出せるし、将来の音声再生にもそのまま使える
(答え合わせの 🔊 が既にこのデータで鳴っている)。

### ダイアトニック暗記の「数えさせない」工夫

一覧を埋める形式は、度数スロットの並びを毎回シャッフルしている。
I から順に並べると「I, II, III… と数えて導く暗唱」になり、
このアプリで抜きたい数えるクセを逆に強化してしまうため。
置けるコードにはダミーが2個混ざっているので、消去法でも解けない。

### なぜ「スケール全部を塗る」のをやめたか

ダイアトニックコードは、どれも親キーと同じ7音を共有する。
つまり「対象コードのスケール構成音を全部塗る」形式にすると、
**コード名を一切見ずに、キーだけ見て機械的に塗れば正解できてしまう**。

> 例: キー Cm で Dm7♭5 が出ても、塗るべき D ロクリアンの音は Cm の7音と完全に一致する。

そこで、答えが必ず**対象コードのルートに依存する「お題」**だけを扱うようにした。

| お題 | タップするもの | タップ数の目安 |
|---|---|---|
| ルート | 対象コードのルート | 2〜3 |
| ガイドトーン | 3rd と 7th | 4〜6 |
| コードトーン | R・3・5・7 | 9〜11 |
| 特性音 | ルート + そのモードらしさを決める音 | 4〜6 |
| オクターブ形 | ◆ で示したルートから1オクターブ分のスケール音 | 8〜9 |

キー Cm のダイアトニック7コードで正解パターンが何通りになるかを数えると:

```
旧・スケール全部 : 7コード中 1通り  (18タップ)   ← コードを見なくても解ける
root            : 7コード中 7通り  (2〜3タップ)
guide           : 7コード中 7通り  (4〜6タップ)
chordTone       : 7コード中 7通り  (9〜11タップ)
octaveShape     : 7コード中 7通り  (8〜9タップ)
```

既定は `ルート / ガイドトーン / コードトーン` の3つをランダムに出す。設定画面の「お題」で変えられる。

### 理論まわりの決め事

- **マイナーキーの V** — 実戦ではドミナントが V7 なので、V7 をダイアトニック側に置き、
  ナチュラルマイナーの Vm7 より重く出す (重み 2.5 : 0.8)。表記は `V7` / `Vm7` で区別する
- **異名同音のキー** — 調号の少ない方を正解とする。同数になる F♯ / G♭ と E♭m / D♯m は
  どちらも正解として併記する
- **音名の表記** — キー内の音はそのキーの調号に従う (F キーなら A♯ ではなく B♭)

### 計測している2つの時間

ポジション・フィルでは、認識速度と運指の定着度を分けて記録する。

- **初手レイテンシ** — 出題表示 〜 最初のタップ。「えーと…」の時間そのもの。**主指標**
- **完了時間** — 最初のタップ 〜 回答確定。運指パターン自体の定着度

セッション結果では**初手レイテンシが長い順**にキーを並べる。これが次に潰すべきキー。

スキップ(「わからない」)・時間切れ・リファレンスを開いた問題は、反射の記録として使えないので
レイテンシの平均からは除外し、正答率側にだけ反映する。

### 難易度

| Lv | 提示情報 |
|---|---|
| 1 | キー + コード名 + ルート位置 + タップした音の度数ラベル + スケール名 |
| 2 | キー + コード名 + ルート位置 |
| 3 | キー + コード名のみ (ルート位置も自分で特定する) |

お題が「ルート」のときは、ルート位置のヒントが答えそのものになるので Lv1〜2 でも出さない。
| 4 | キー + コードが鳴るだけ (コード名は非表示。🔊 で再生し直せる) |

## フレット範囲 (24F まで)

出題範囲は 詳細設定 → フレット範囲 で `0/1/5/12F〜` × `〜12/15/19/24F` から選ぶ。
**既定は 0〜12F**(弾き慣れた範囲から始まるように)。`〜24F` にすると窓はネック全域にばらけて配置される。
下限と上限が近すぎて窓を置けない組み合わせは、選んだ側を優先して自動で片方をずらす。

指板が13フレットを超える表示になるときは、縮小せずに等倍のままフレット方向へスクロールする。
このとき開放弦の音名は流れていかないよう固定表示になり、注目すべきフレット
(音名当ての出題位置 / ポジション・フィルのルート / リファレンスの選択ボックス) が
自動で画面中央に来る。

リファレンスのボックス表示も 24F ならネック全域ぶん並ぶ。
たとえば Am ペンタは `0-4 / 3-7 / 5-9 / 8-12 / 10-14` の定番5ボックスに続けて
`12-16 / 15-19 / 17-21 / 20-24` とオクターブ上も出る。

## 遊び方が分からなくなったら

- **モード選択画面**: 選んだモードの下に「何をするゲームか」と「何のための練習か」が出る。
  `遊び方をくわしく →` で手順とコツの全文が開く
- **プレイ中**: 画面の上に1行の説明が常に出ている。末尾の `?` を押すと同じ全文が開く
- **リファレンス**: 見出し横の `?`

説明の文面は [src/components/Help.tsx](src/components/Help.tsx) の `HELP` にまとまっている。

## 操作

- 指板はドラッグでなぞって連続入力できる。もう一度タップで解除
- 全部埋まると自動判定、途中でも「回答」で判定
- 出題範囲は青い枠で囲まれ、その前後3フレットは暗く描かれる (枠外は押せない)
- 弦と弦のあいだの薄いひし形は指板のポジションマーク(3・5・7・9・12F…)。音符ではない
- 判定後は正解パターン(緑=正解 / 点線=不足 / 赤=余分)とスケール名を表示してから次問へ。
  間違い・スキップのときは読む時間を長めに取る

## 起動から出題まで2タップ

ホーム最上部の「前回と同じ設定で開始」で、前回のモード・難易度・キー・セッション長のまま始まる。
設定は localStorage に保存される。

## データ

セッション履歴・キー別統計・各種設定はすべて **localStorage** にのみ保存される。
サーバ送信は一切ない。設定画面から履歴を削除できる。

## 構成

```
src/
  music/
    notes.ts       音名・キーの綴り (F# / Bb を文脈に沿って正しく出す)
    scales.ts      スケール定義。度数ラベルを唯一の定義元にして半音数を導出
    chords.ts      ダイアトニック / セカンダリードミナント / モーダルインターチェンジ
    fretboard.ts   チューニング、ポジション計算、フレット窓の自動配置、ボックス分割
    tasks.ts       ポジション・フィルのお題と、その正解位置の計算
    analysis.ts    進行からキーを判定する。出題の一意性チェックにも使う
    progressions.ts 進行テンプレート (キー + 度数) と、一意に決まる進行の生成
  components/
    Fretboard.tsx  SVG 指板。横向き/縦向き・左利き反転・ドラッグ入力・窓のグレーアウト
    ui.tsx         ボタン等の小物
  screens/         各モードの画面 + セッション進行 + 結果サマリー
  session/
    generator.ts   出題生成
  storage.ts       localStorage 永続化とキー別統計の集計
  audio.ts         Web Audio (Lv4 のコード再生、正誤フィードバック)
```

### 設計メモ

- **スケールの定義元は度数ラベル**。`['1','b3','4','b5','5','b7']` から半音数も綴りも導出するので、
  C blues が `C Eb F Gb G Bb` のように正しく綴られる
- **フレット窓の配置**は、対象コードのルートが窓内に入る候補を全部集めて重み付きランダムで選ぶ。
  低音弦にルートがある窓をやや優先しつつ、ネックの高さがばらけるようにしている
  (毎回同じ場所に出ると位置の丸暗記になってしまうため)。24F 設定なら 0〜20F 開始が
  ほぼ均等に出る
- **キー×度数の誤答選択肢**は、ランダムではなく「響きが同じ」「ルートが半音〜全音違い」を優先する。
  さらに `buildConfusion()` が過去の取り違え(正解ディグリー → 実際に選んだディグリー)を集計し、
  一度間違えた相手を次から選択肢に混ぜる
- **ボックス分割**は最低音弦上にスケール音が現れるフレットを起点にする。
  ペンタなら定番の5ボックス、7音スケールなら7ポジションになり、ネックを長く取れば
  その上のオクターブぶんも続く。端で幅が足りない半端な窓は作らない
